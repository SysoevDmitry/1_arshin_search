## 📖 ОПИСАНИЕ

Консольное приложение для пакетной обработки запросов к ФГИС АРШИН из Excel-файлов. Предназначено для работы на серверах, удалённых машинах и в автоматизированных сценариях.

**Ключевые особенности:**
- ✅ Работа без GUI (терминал/SSH/tmux/screen)
- ✅ Параллельные запросы к API (до 10 одновременных)
- ✅ UPSERT (INSERT OR REPLACE) — перезапись существующих записей
- ✅ DB-прогресс (search_progress) — атомарное сохранение прогресса в SQLite
- ✅ Прогноз оставшегося времени в часах/днях в прогресс-баре
- ✅ Надёжное продолжение после сбоя (--resume / --no-resume)
- ✅ Экспорт БД без повторного поиска (--export-only)
- ✅ Автоматическое определение колонок Excel (алгоритм наилучшего совпадения)
- ✅ Сохранение ведущих нулей в серийных номерах
- ✅ Сохранение связей с исходными данными
- ✅ Проверка на полную уникальность (13 полей)
- ✅ Экспорт с русскими заголовками
- ✅ Учёт года выпуска прибора (поиск от года выпуска)
- ✅ Атрибутивный поиск (рекомендуется спецификацией ФГИС)
- ✅ Поддержка конкретной даты поверки (--verification-date)
- ✅ Получение записи по vri_id (--get-record)
- ✅ Автоматическое имя выходного файла (дата + номер)
- ✅ Автосоздание venv и установка зависимостей (run.sh)
- ✅ Поддержка ARM/Armbian (run_armbian.sh)
- ✅ Фоновый watchdog с авто-восстановлением (Windows, run_bg.ps1)
- ✅ Логи в папке `Logs/`

## 🚀 БЫСТРЫЙ СТАРТ

### Linux (x64)

```bash
chmod +x run.sh
./run.sh -f запрос.xlsx -y 2020-2025 -o результат.csv
```

### Linux ARM (Armbian, Raspberry Pi)

```bash
chmod +x run_armbian.sh
./run_armbian.sh -f запрос.xlsx -y 2020-2025 -o результат.csv
```

### Windows PowerShell

```powershell
.\run.ps1 -File запрос.xlsx -Years 2020-2025 -Output результат.csv
```

### Windows — фоновый watchdog

```powershell
.\run_bg.ps1 -File запрос.xlsx -Years 2020-2025 -Output результат.csv
.\run_bg.ps1 --status
.\run_bg.ps1 --stop
```

> **Примечание:** `run.sh` и `run_armbian.sh` **сами запускают `main.py`** — не нужно передавать `main.py` в аргументах. Если вы по ошибке передали `main.py`, скрипт автоматически его проигнорирует.

### Без скриптов (любая ОС)

```bash
pip install pandas openpyxl aiohttp tqdm
python main.py -f запрос.xlsx -y 2020-2025 -o результат.csv
```

## 📋 ПАРАМЕТРЫ КОМАНДНОЙ СТРОКИ

| Параметр | Краткий | Описание | Пример |
|----------|---------|----------|--------|
| `--file` | `-f` | Excel файл с запросами | `-f запрос.xlsx` |
| `--years` | `-y` | Годы поиска | `-y 2020,2021,2022` или `-y 2020-2025` |
| `--output` | `-o` | Файл для экспорта (CSV) | `-o результат.csv` |
| `--verification-date` | — | Дата поверки (yyyy-MM-dd), приоритет над --years | `--verification-date 2024-05-15` |
| `--attribute-search` | — | Атрибутивный поиск (рекомендуется) | `--attribute-search` |
| `--resume` | — | Принудительно продолжить с места сбоя | `--resume` |
| `--no-resume` | — | Игнорировать прогресс, начать заново | `--no-resume` |
| `--export-only` | — | Только экспорт БД в CSV (без поиска) | `--export-only результат.csv` |
| `--get-record` | — | Получить запись по vri_id | `--get-record 2-162158132` |
| `--template` | — | Создать шаблон Excel | `--template шаблон.xlsx` |
| `--stats` | — | Показать статистику БД | `--stats` |
| `--clear` | — | Очистить базу данных | `--clear` |
| `--concurrent` | — | Кол-во одновременных запросов (3-10) | `--concurrent 5` |

### Примеры использования

```bash
# Поиск по Excel файлу (по годам)
./run.sh -f запрос.xlsx -y 2020,2021,2022 -o результат.csv

# Поиск по диапазону годов
./run.sh -f данные.xlsx -y 2020-2025 -o export.csv

# Поиск по конкретной дате поверки
./run.sh -f данные.xlsx --verification-date 2024-05-15 -o export.csv

# Атрибутивный поиск (рекомендуется спецификацией)
./run.sh -f запрос.xlsx -y 2024 --attribute-search

# Продолжить после сбоя (авто-определение прогресса)
./run.sh -f запрос.xlsx -y 2020-2025

# Принудительно продолжить / начать заново
./run.sh -f запрос.xlsx --resume
./run.sh -f запрос.xlsx --no-resume

# Экспорт БД без повторного поиска
./run.sh --export-only результат.csv

# Получить запись по vri_id
./run.sh --get-record 2-162158132

# Создать шаблон Excel
./run.sh --template шаблон.xlsx

# Статистика БД
./run.sh --stats

# Очистить БД
./run.sh --clear

# Увеличенный параллелизм (для стабильного API)
./run.sh -f запрос.xlsx -y 2020-2025 --concurrent 10

# Уменьшенный параллелизм (при ошибках 429)
./run.sh -f запрос.xlsx -y 2020-2025 --concurrent 3
```

## 📥 ПРОДОЛЖЕНИЕ ПОСЛЕ СБОЯ

Приложение сохраняет прогресс в таблицу `search_progress` базы SQLite **после каждого запроса**. При повторном запуске с тем же файлом:

1. Обнаруживает сохранённый прогресс
2. Предлагает продолжить с последней позиции
3. Если количество запросов изменилось — предупреждает
4. После успешного завершения прогресс автоматически очищается

```bash
# Авто-определение (интерактивный диалог):
./run.sh -f запрос.xlsx -y 2020-2025

# Принудительное продолжение:
./run.sh -f запрос.xlsx -y 2020-2025 --resume

# Принудительный старт заново:
./run.sh -f запрос.xlsx -y 2020-2025 --no-resume
```

## 💾 СТРАТЕГИЯ СОХРАНЕНИЯ (UPSERT)

Новые записи с существующим `vri_id` **перезаписывают** старые (INSERT OR REPLACE), при этом сохраняется оригинальное время `collected_at`. Это позволяет обновлять данные без создания дублей.

При запуске поиска, если в базе уже есть записи, программа предложит:

```
📊 В базе уже есть 12 записей
  очистить / yes — удалить все записи и начать заново
  добавить / no  — добавить/обновить записи (UPSERT)
🗑  Ваш выбор:
```

## 📊 СТРУКТУРА EXCEL-ФАЙЛА

### Поддерживаемые колонки

| Колонка | Описание | Пример | Обязательно |
|---------|----------|--------|-------------|
| **Заводской номер** | Серийный номер прибора | `12345678` | ✅ |
| Наименование | Тип прибора | `Счетчик электрической энергии...` | ❌ |
| Номер в реестре | Номер в реестре СИ | `77310-20` | ❌ |
| **Id_ПУ** | Идентификатор точки учёта | `ПУ-001` | ❌ |
| **Год выпуска** | Год выпуска прибора | `2023` | ❌ |
| **Номер договора** | Договор с поставщиком | `Д-001/2023` | ❌ |
| **Код ЭДО** | Код электронного документооборота | `123456789` | ❌ |
| **МПИ** | Межповерочный интервал | `16` | ❌ |
| Балансовая принадлежность | Баланс | `ООО "Ромашка"` | ❌ |
| Эксплуатационная ответственность | Эксплуатация | `ООО "Ромашка"` | ❌ |

> **Обязательное поле:** `Заводской номер`. Остальные колонки заполняются по желанию.

### Год выпуска прибора

Если в строке указан год выпуска (колонка «Год выпуска»), поиск для этой строки идёт от года выпуска до конца указанного диапазона.
Например: `-y 2015-2026` + год выпуска `2023` → поиск `2023-2026`.

### Ведущие нули в серийных номерах

Программа сохраняет ведущие нули (например, `023241147596`). Все колонки читаются как текст — формат ячеек Excel не имеет значения.

### Автоматическое распознавание

Программа распознаёт альтернативные названия колонок (алгоритм выбирает наилучшее совпадение):

```
'серийный номер' → mi_number
'заводской номер' → mi_number
'номер пу' → mi_number
'id_пу' → id_pu
'год выпуска' → manufacture_year
'номер договора' → contract_number
'код эдо' → edo_code
'мпи' → mpi
```

## 🗄️ БАЗА ДАННЫХ

### Проверка на уникальность (13 полей)

Запись считается уникальной по комбинации полей:

```python
(vri_id, mit_number, mit_title, mi_number, verification_date,
 valid_date, applicability, org_title, result_docnum,
 manufacturer, search_query, row_index, id_pu)
```

**Преимущество:** Одна запись API может быть сохранена несколько раз для разных строк Excel (разные Id_ПУ, договоры и т.д.)

При выборе «добавить» дубли автоматически фильтруются. При включённом UPSERT существующие записи перезаписываются.

## 🔧 АВТОМАТИЗАЦИЯ

### Запуск через cron (Linux)

```bash
# Ежедневный запуск в 02:00
0 2 * * * cd ~/Загрузки/Приборы_учета/Konsol_Excel && ./run.sh -f запрос.xlsx -y 2026
```

### Запуск в tmux/screen (фоновая работа)

При обработке больших файлов поиск может идти часами. Чтобы не держать терминал открытым, используйте **tmux** или **screen** — виртуальные терминалы, которые продолжают работу после отключения.

#### tmux

```bash
# 1. Создать новую сессию и подключиться
tmux new -s arshin

# 2. Внутри сессии — запустить поиск
cd ~/Загрузки/Приборы_учета/Konsol_Excel
./run.sh -f Запрос_100.xlsx -y 2015-2026 -o результат.csv

# 3. Отключиться от сессии (поиск продолжается в фоне)
# Нажать: Ctrl+B, затем D

# 4. Вернуться к сессии позже
tmux attach -t arshin

# 5. Посмотреть список активных сессий
tmux ls

# 6. Завершить сессию (когда работа закончена)
tmux kill-session -t arshin
```

#### screen

```bash
# 1. Создать новую сессию
screen -S arshin

# 2. Внутри сессии — запустить поиск
cd ~/Загрузки/Приборы_учета/Konsol_Excel
./run.sh -f Запрос_100.xlsx -y 2015-2026 -o результат.csv

# 3. Отключиться от сессии
# Нажать: Ctrl+A, затем D

# 4. Вернуться к сессии
screen -r arshin

# 5. Посмотреть список сессий
screen -ls

# 6. Завершить сессию (внутри сессии)
exit
# или снаружи:
screen -S arshin -X quit
```

```bash
tail -f Logs/arshin_excel_*.log
```

## 🐛 РЕШЕНИЕ ПРОБЛЕМ

### Много дублей в экспорте

**Это нормально!** Проверка на полную уникальность позволяет сохранять одну запись API для разных строк Excel (разные Id_ПУ, договоры).

### Ошибки 429 (Too Many Requests)

```bash
./run.sh -f запрос.xlsx -y 2020-2025 --concurrent 3
```

### Ошибка «unrecognized arguments: main.py»

**Не передавайте `main.py` в `run.sh`!** Скрипт сам запускает `main.py`:

```bash
./run.sh -f запрос.xlsx -y 2020-2025    # ✅ Правильно
./run.sh main.py -f запрос.xlsx ...     # ❌ Неправильно (хотя скрипт теперь игнорирует)
```

### Не определяются колонки Excel

1. Проверьте названия колонок (должны совпадать с поддерживаемыми)
2. Убедитесь, что файл в формате `.xlsx` (не `.xls`)
3. Проверьте первую строку — это должны быть заголовки
4. Посмотрите лог: программа выводит какие колонки определила

### Пустой результат поиска

1. Проверьте правильность номеров приборов
2. Убедитесь, что данные есть в реестре за указанные годы
3. Проверьте логи в `Logs/arshin_excel_*.log`

### Ведущие нули потерялись

Все колонки читаются как текст. Если нули теряются — очистите `__pycache__/` и перезапустите.
