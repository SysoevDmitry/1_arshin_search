# ФГИС АРШИН — Konsol_Excel v6.3 (объединённая версия)

Консольное приложение для пакетной обработки запросов к **ФГИС АРШИН** — федеральной государственной информационной системе «АРШИН» (единый реестр средств измерений РФ).

**Версия 6.3** объединяет лучшие решения двух веток разработки:
- **UPSERT (INSERT OR REPLACE)** — перезапись существующих записей свежими данными с сохранением оригинального времени `collected_at`
- **DB-прогресс (search_progress)** — атомарное сохранение прогресса в SQLite для надёжного продолжения после сбоев
- **--export-only** — экспорт существующей БД в CSV без повторного поиска
- **Гибкое управление продолжением** — `--resume` / `--no-resume` / интерактивный диалог

## Возможности

- **Пакетная обработка Excel-файлов** со списком серийных номеров
- **Параллельные запросы к API** (до 10 одновременных через asyncio)
- **Атрибутивный поиск** по `mi_number` (рекомендован спецификацией ФГИС)
- **Автоматическое определение колонок** Excel (90+ ключевых слов)
- **Сохранение ведущих нулей** в серийных номерах (dtype=str)
- **Учёт года выпуска** — сужение диапазона поиска
- **Фильтрация электросчётчиков** — двухэтапная (exclude/include словари)
- **Точное совпадение серийных номеров** — нормализация + сравнение без ведущих нулей
- **UPSERT-стратегия** — существующие записи перезаписываются (не дублируются)
- **Надёжное продолжение** после сбоя (DB-прогресс)
- **Экспорт в CSV** с русскими заголовками (21 поле, разделитель `;`)
- **Логирование** в `Logs/arshin_excel_YYYYMMDD_HHMMSS.log`
- **Генерация шаблона Excel** (`--template`)
- **Статистика БД** (`--stats`)
- **Получение записи по vri_id** (`--get-record`)
- **Экспорт БД без поиска** (`--export-only`)
- Обработка ошибок API: 408 (Timeout), 429 (Rate Limit), 502 (Bad Gateway), 5XX (серверные)

## Требования

- Python 3.8+
- Зависимости: `pandas`, `openpyxl`, `aiohttp`, `tqdm`

## Быстрый старт

### Linux
```bash
chmod +x run.sh
./run.sh -f запрос.xlsx -y 2020-2025 -o результат.csv
```

> **Примечание:** `run.sh` и `run_armbian.sh` **сами запускают `main.py`** — не нужно добавлять `main.py` в аргументы. Если по ошибке передали, скрипт автоматически проигнорирует.

### Linux ARM (Armbian, Raspberry Pi)
```bash
chmod +x run_armbian.sh
./run_armbian.sh -f запрос.xlsx -y 2020-2025 -o результат.csv
```

### Windows PowerShell
```powershell
.\run.ps1 -File запрос.xlsx -Years 2020-2025 -Output результат.csv
```

### Фоновый watchdog с авто-восстановлением (Windows)
```powershell
.\run_bg.ps1 -File запрос.xlsx -Years 2020-2025 -Output результат.csv
# Проверить статус:
.\run_bg.ps1 --status
# Остановить:
.\run_bg.ps1 --stop
```

### Без скриптов (любая ОС)
```bash
pip install pandas openpyxl aiohttp tqdm
python main.py -f запрос.xlsx -y 2020-2025 -o результат.csv
```

## Использование

### Основные команды

```bash
# Поиск по годам
python main.py -f запрос.xlsx -y 2020,2021,2022 -o результат.csv

# Поиск по диапазону годов
python main.py -f данные.xlsx -y 2020-2025 -o export.csv

# Поиск по конкретной дате поверки (приоритет над годами)
python main.py -f данные.xlsx --verification-date 2024-05-15 -o export.csv

# Атрибутивный поиск (рекомендуется спецификацией)
python main.py -f запрос.xlsx -y 2024 --attribute-search

# Продолжить после сбоя
python main.py -f запрос.xlsx -y 2020-2025 --resume

# Начать заново (игнорировать прогресс)
python main.py -f запрос.xlsx -y 2020-2025 --no-resume

# Экспорт БД без поиска
python main.py --export-only результат.csv

# Получить запись по vri_id
python main.py --get-record 2-162158132

# Статистика БД
python main.py --stats

# Очистить БД
python main.py --clear

# Создать шаблон Excel
python main.py --template шаблон.xlsx
```

### Формат Excel-файла

Колонки определяются автоматически. Рекомендуемый набор:
| Заводской номер | Наименование | Номер в реестре | Id_ПУ | Номер договора | Код ЭДО | МПИ |
|---|---|---|---|---|---|---|
| 12345678 | Счетчик эл. энергии Меркурий 201 | 77310-20 | ПУ-001 | Д-001/2023 | 123456789 | 16 |

### Продолжение после сбоя

Приложение сохраняет прогресс в таблицу `search_progress` базы SQLite **после каждого запроса**. При повторном запуске с тем же файлом:
1. Обнаруживает сохранённый прогресс
2. Предлагает продолжить с последней позиции
3. Если количество запросов изменилось — предупреждает
4. После успешного завершения прогресс автоматически очищается

### Стратегия сохранения (UPSERT)

Новые записи с существующим `vri_id` **перезаписывают** старые (INSERT OR REPLACE), при этом сохраняется оригинальное время `collected_at`. Это позволяет обновлять данные без создания дублей.
