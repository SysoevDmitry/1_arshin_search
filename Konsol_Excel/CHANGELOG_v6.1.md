#### 4. Атрибутивный поиск (рекомендация раздела 4)

**Спецификация:** раздел 4 «Рекомендации по использованию»

> Используйте атрибутивный поиск вместо search:
> - Поиск только в нужных атрибутах
> - Более высокая скорость
> - Возможность поиска значений с пробелами без дополнительной проверки

**Реализация:**
- Новый параметр `filters` для атрибутивных фильтров
- Поддержка фильтров: `mi_number`, `mit_number`, `org_title` и др.
- Подстановочные символы `*` и `?`
- Командная строка: `python main.py --attribute-search`

**Файл:** `api_client.py`, `collector.py`, `main.py`

**Пример использования:**
```bash
# Атрибутивный поиск (по умолчанию включен)
python main.py -f запрос.xlsx -y 2024 --attribute-search

# В коде:
await api.search_with_retry(
    search_term=None,  # Не используется search
    year=2024,
    filters={'mi_number': '123*'}  # Атрибутивный фильтр
)
```

**Поддерживаемые фильтры (из спецификации):**
- `mi_number` — Заводской номер
- `mit_number` — Номер в реестре типов СИ
- `mit_title` — Наименование типа СИ
- `org_title` — Организация-поверитель
- `verification_date` — Дата поверки
- `valid_date` — Действительна до
- `applicability` — Пригодность (true/false)
- `result_docnum` — Номер документа о поверке

### 🐛 Решение проблем

#### Ошибка 408 Request Timeout

**Причина:** Превышен лимит времени на поиск (сложный запрос)

**Решение:**
1. Используйте атрибутивный поиск вместо `search`
2. Уменьшите количество подстановочных символов
3. Увеличьте количество фиксированных символов в строке поиска

#### Ошибка 5XX

**Действия:**
1. Проверьте лог-файл `arshin_excel_*.log`
2. Скопируйте детали ошибки (время, URL, параметры)
3. Отправьте на `fgis2@rst.gov.ru`

#### Запись неактуальна (publication.status)

**Причина:** Данные были изменены после кэширования

**Решение:** Выполните повторный поиск
